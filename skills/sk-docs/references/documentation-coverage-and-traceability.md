# Documentation coverage and traceability

| Document concern | Expected evidence |
|---|---|
| Scope/standard | Document type, intended audience, standard or Diátaxis mode and owner |
| Claims | Source path/section, code/test/artifact link or explicit `Gap`/`Unknown` |
| Requirements | Stable `FR-*`, `NFR-*`, `BR-*` IDs and requirement → design → code/test trace |
| Architecture | Stakeholder concern, viewpoint, decision/ADR link and affected boundaries |
| Completeness | Coverage matrix status: `complete`, `partial`, `gap` or `N/A (reason)` |
| Freshness | Last-synced commit/date, change trigger and review owner |
| Rendered output | Representative pages/diagrams, links, headings, tables and code samples reviewed |
| Handoff | Next document owner, unresolved gaps and update trigger |

Golden documentation is not “all headings filled”: it is a source-traceable set that makes gaps visible and preserves a single Markdown source of truth. Mark non-applicable sections explicitly instead of deleting them.
