Goal & Outcome

Goal

User with email in system can reset password by receiving OTP via email and verifying within 5 minutes, with 0 security breaches in production.

Outcome

  • User enters email → receives OTP in <30 seconds
  • User enters correct OTP + new password → password updated, redirect to login
  • User enters wrong OTP 3 times → account locked 15 minutes, show message "Account locked. Try again in 15 minutes"
  • OTP expired (>5 minutes) → show message "OTP expired. Request new OTP"
  • User requests OTP >3 times/minute → rate limited, show message "Too many requests. Try again later"

Context

Facts

  • System has existing OTP service: auth/otp_service.py (generate_otp, verify_otp, send_otp_email)
  • Email service configured: SMTP host=smtp.company.com, port=587
  • Database schema: users table has email, password_hash, otp_code, otp_expiry, failed_attempts, locked_until
  • Existing password policy: min 8 chars, 1 uppercase, 1 lowercase, 1 digit, 1 special char

Constraints

Constraint Source
Timebox: 2 days (Sprint 24, commit by Aug 10) user
Stack: Python 3.11, FastAPI, PostgreSQL 15 repo
Security: OTP must comply with OWASP ASVS v4.0 §3.2 user
No SMS gateway available (email only) repo

Scope

In

  • Email OTP generation (6-digit numeric)
  • OTP delivery via email (subject: "Your password reset code")
  • OTP verification (5-min expiry, single-use)
  • Password update after verify success
  • Account lockout after 3 failed attempts (15-min lock)
  • Rate limit: 3 OTP requests/minute/email

Out

  • SMS OTP delivery (no SMS gateway)
  • TOTP app integration (Google Authenticator, Authy)
  • 2FA for login (only applies to change password)

Non-goals

  • Real-time OTP delivery tracking (email sent/delivered/opened)
  • Password strength meter UI
  • Multi-language email templates (English only)
