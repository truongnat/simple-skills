Options or states

Recommended

Option A — JWT (JSON Web Tokens)

Stateless authentication
Token: {user_id, role, exp}
Stored: Client-side (localStorage/cookie)

Benefits: Scalable, no server state, works well for microservices

Limitations: Can't revoke tokens easily, larger payload size

Risk: Token theft = account compromise until expiry

Option B — Session-based

Stateful authentication
Session ID: uuid-v4
Stored: Server-side (Redis/DB) + cookie

Benefits: Easy revocation, smaller cookies, better security control

Limitations: Requires server state, harder to scale horizontally

Risk: Session store becomes single point of failure

Option C — OAuth 2.0 + OpenID Connect

Delegated authentication
Provider: Google/GitHub/Auth0
Flow: Authorization Code + PKCE

Benefits: No password management, social login, enterprise-ready

Limitations: External dependency, complex implementation, UX friction

Risk: Provider downtime = login unavailable
